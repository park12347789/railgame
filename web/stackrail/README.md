# STACKRAIL — 이끼역

카드를 쌓아 직원을 배치하고, 3D 기차의 도착·상차·출발을 관리하는 웹 프로토타입입니다. 기존 Unity 프로젝트와 독립적인 `web/stackrail/` 폴더입니다.

## 실행

Node.js 22에서 검증했습니다. 외부 패키지를 설치하지 않습니다.

```sh
cd web/stackrail
npm start
```

브라우저에서 `http://127.0.0.1:8765`를 여세요. 포트는 `PORT` 환경 변수로 바꿀 수 있습니다. 로컬 서버는 본인 컴퓨터에서만 접근하도록 바인딩합니다.

```sh
npm test
npm run build
```

`npm run build`는 CSS와 JavaScript를 모두 포함한 `dist/index.html`을 만듭니다. 이 파일 하나로 오프라인 실행이 가능합니다. 다운로드한 파일은 HTML 미리보기 앱이 아니라 JavaScript를 실행하는 웹브라우저로 열어야 합니다. 파일 직접 열기의 저장 지원은 브라우저마다 다릅니다. 진행 저장은 로컬 서버 실행을 권장합니다.

GitHub 소스 링크는 공개 플레이 주소가 아닙니다. 이 변경에는 GitHub Pages 설정 변경이나 배포가 포함되지 않습니다. 별도 정적 호스팅에는 빌드한 `dist/`를 배포하면 됩니다.

## 플레이

1. 직원 카드를 누른 다음 시설을 누르거나, 직원 카드를 시설로 드래그합니다.
2. 승객은 발권소, 목재·광석은 화물장, 식품은 매점, 부품은 정비소에 놓습니다.
3. 작업 결과는 알맞은 정차 열차에 자동 적재됩니다. 만차가 되면 관제 패널에서 출발시켜 수익을 받습니다.

직원과 시설은 사라지지 않으며 물자만 소비됩니다. 직원 여러 명을 한 시설에 배치할 수 있습니다. 한 번에 최대 6개, 시설마다 최대 12개를 대기열에 넣습니다. 직원 대기실로 회수하거나 시설의 회수 버튼으로 대기 물자를 돌려받을 수 있습니다.

**목표:** 4일 안에 자금 750 G와 만차 출발 6편을 동시에 달성합니다. 하루는 시뮬레이션 시간 90초입니다. 평판 0, 자금 -100 G 미만, 목표를 못 채운 4일 종료는 실패입니다. 성공 후 자유 운영이 가능합니다.

| 기능 | 내용 |
|---|---|
| 열차 | 여객·화물열차, 진입/정차/출발, 실제 적재량 시각화, 일부 고장 |
| 역 운영 | 4개 시설, 3명 시작/최대 5명 직원, 입고/작업/자동 적재 |
| 확장 | 두 번째 승강장, 직원 채용, 창고 확장, 작업 속도, 자동 분류 |
| 압박 | 지연 평판 감소, 창고 초과, 유지비, 미완료 출발 |
| 조작 | 카드 클릭·탭·드래그, 카메라 회전·확대, 일시정지 중 배치 |
| 편의 | 1/2/4배속, 도움말, 다시 시작 확인, 브라우저 자동 저장 시도 |

Space는 일시정지, 숫자 1/2/3은 1/2/4배속입니다. 화면을 떠나면 자동으로 일시정지합니다. 소리는 기본 꺼짐이며 음표 버튼으로 켭니다.

## 구조와 에셋

- `src/sim.js`: DOM과 독립적인 결정적 운영 시뮬레이션 및 저장 검증.
- `src/render.js`: 자체 WebGL 렌더러, 절차적 삼각형 메시. WebGL 미지원 시 같은 3D 메시를 Canvas 2D로 투영하는 소프트웨어 렌더러를 사용합니다.
- `src/game.js`: 카드 입력, HUD, WebAudio 효과, 자동 저장, 게임 루프.
- `index.html`, `style.css`: 한국어 UI와 반응형 레이아웃.
- `serve.cjs`, `build.cjs`: 외부 의존성 없는 실행 서버와 단일 파일 빌드.

모델·아이콘·효과음은 코드로 만들었습니다. Stacklands의 아트나 소스는 사용하지 않았습니다. 외부 CDN, 폰트 파일, 이미지, 계정, API 키, 원격 텔레메트리가 없습니다. 게임 규칙의 영감을 받은 프로토타입이지 공식 연계작이 아닙니다.

## 검증 및 한계

`npm test`: 22개 통과. 자금이나 물자를 편집하지 않는 자동 운영 정책으로 825 G / 만차 9편 승리 확인. 브라우저 UI 테스트는 데스크톱 드래그, 모바일 크기 터치, 두 승강장 운행, 카메라, 일시정지를 검사합니다.

브라우저 테스트 실행에는 별도로 Python과 Playwright, Chromium이 필요합니다.

```sh
npm run build
python -m pip install playwright
python -m playwright install chromium
# 설치한 Chromium 경로를 CHROMIUM_PATH 환경 변수에 설정하세요.
python tests/browser_smoke.py
```

테스트 기본 브라우저 경로는 `/usr/bin/chromium`입니다. 테스트의 인메모리 문서에서만 진단 API를 켭니다. 일반 게임은 `?test=1`을 붙였을 때만 진단 API를 노출합니다.

GPU 하드웨어 렌더링, 실제 사이트 origin의 저장 지속성, Android/iOS 실기기는 아직 검증하지 않았습니다. 이번 브라우저 검증은 네트워크 이동이 제한된 환경에서 소프트웨어 3D 경로와 인메모리 HTML 문서를 사용했습니다. 자세한 내용은 `TEST_REPORT.md`를 참고하세요.

선로 직접 건설, 운전 조작, 자유 위치 카드 물리, 대규모 생산 체인은 구현 범위가 아닙니다. 카드 쌓기는 고정 시설의 직원/물자 작업 대기열로 구현했습니다.
